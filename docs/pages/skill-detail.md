# Skill Detail Page Requirements

Last updated: 2026-09-01

## Page identity

- Public route: `skill-detail.html`
- Product role: focused detail view for one Skill resource
- Canonical implementation: `src/features/skills/skill-detail.js`, `src/features/skills/skill-detail.css`
- Canonical data source: `src/features/skills/skills-data.js`

## Page goal

Provide enough focused information about one Skill for a user to understand what it does, how it is useful and where to continue.

## Core user task

A user opening a Skill detail should be able to answer:

- What is this Skill?
- What problem does it help solve?
- How can I use or access it?
- Is there source code / an official repository / an external resource?

## Core functions

- Display one selected Skill and its essential metadata.
- Explain its value concisely.
- Provide the correct original / repository / official destination where available.
- Surface reusable prompt or usage guidance only when it materially helps.
- Provide a clear way back to `skills.html` while preserving relevant directory state.

## Information structure

1. Skill identity
2. Short purpose / use case
3. Key capabilities or usage notes
4. Source / official link / action
5. Return to Skills directory

## Interaction rules

- Keep the page focused on one item.
- Avoid rebuilding the entire Skills directory inside the detail page.
- Do not duplicate global navigation.
- Chinese and English content should remain equivalent where translations exist.
- Every `repo` value generated by `skills.html` must resolve to exactly one record in `skills-data.js`.
- The detail page must load its own data through ES modules. It must not depend on `skills.html` or `skills.js` having executed first.
- External source actions must prefer `skillOfficialPages[repo]` when one is defined; otherwise they may fall back to `https://github.com/{repo}`.
- Source action copy must remain truthful even when the destination is an official website rather than GitHub.

## Keep

- Clear resource identity.
- Source / official destination.
- Concise usage context.
- Existing `repo` query parameter as the stable detail-page identifier.

## Remove / avoid

- Dense unrelated recommendations.
- Full directory filtering controls.
- Launcher configuration features.
- Duplicate catalog state that belongs in `skills-data.js`.
- Loading `skills.js` as a classic script from the detail page.
- Hard-coding every external action to the repository root when a more accurate official destination exists.

## Regression checks

Before shipping a Skill detail change:

1. Open at least one normal repository item, one item with a custom `skillOfficialPages` URL, and one multi-skill repository such as `emilkowalski/skills`.
2. Confirm title, description, category, source action, copy buttons and back navigation populate without console/module errors.
3. Confirm both `lang=zh` and `lang=en` resolve the same item.
4. Confirm an unknown `repo` shows the not-found state instead of silently displaying another Skill.

## Modification boundary

This page is only for focused Skill detail. Any change that primarily improves browsing across many resources belongs in `skills.html` instead.
