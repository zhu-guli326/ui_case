# Catalog Agent Rules

## Generated output
- `catalog/index.js` is generated by `scripts/build_catalog.mjs` and is not a source-of-truth file.
- Do not open or edit `catalog/index.js` for normal catalog changes.
- Do not load the full generated bundle to find one case, style, brand, or component.

## Edit the smallest source file
- UI cases: `catalog/cases/<case-id>.json`
- Style profiles: `catalog/styles/<style-id>.json`
- Brand profiles: `catalog/brands/<brand-id>.json`
- Component references: `catalog/components/<component-id>.json`
- Theme presets: `catalog/color-themes.js`
- Font presets: `catalog/font-presets.js`

## Search strategy
- Start from the exact case/style/brand/component id.
- Read one matching JSON file first.
- Only inspect adjacent source files when the requested change genuinely spans multiple records.
- Never recursively read all catalog JSON files just to understand one record.

## Generated catalog rebuild
- After changing source JSON, rebuild with `npm run build:catalog` when the execution environment supports it.
- Treat `catalog/index.js` only as build output / runtime compatibility surface.
- If validating generated output, use `npm run build:catalog -- --check` or the repository's existing validation command rather than manually reviewing the whole generated file.
